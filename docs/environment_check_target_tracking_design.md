# 환경 점검과 운동 대상자 추적의 경계

## 현재 구현

`POST /api/environment-checks`는 운동 시작 전에 원본 웹캠 이미지 한 장에서 YOLO `person` 객체 수를 확인한다. 사람 한 명이 충분히 크게 보이면 `PASS`를 반환한다. 이 호출은 Track ID를 발급하거나 동일인을 지속적으로 추적하지 않는다.

프론트는 공통 가이드 영역에서 MediaPipe로 머리·양손·양발과 랜드마크 가시성을 연속 확인하고, 정상 상태를 프론트 설정 시간 동안 유지한 뒤에만 자동으로 기존 운동 시작 흐름으로 이동한다. 가이드 영역은 표시용이며 YOLO 입력을 자르지 않는다. YOLO와 MediaPipe는 모두 원본 프레임 좌표를 사용하고, 거울 표시 반전은 UI에만 적용한다.

## 운동 중 대상 유지

운동 시작 후에는 기존 MediaPipe 추적 결과를 원래 운동 대상으로 계속 사용해야 한다. 다른 사람이 잠시 등장해도 새 사람에게 점수·대상을 자동 전환하지 않는다. 원래 대상의 랜드마크가 가려지거나 구분할 수 없으면 새 대상을 고르지 않고 기존 이탈/일시정지 흐름으로 넘긴다.

이 저장소에는 MediaPipe 스트림 처리나 2초 이탈·0.6초 복귀 구현이 없으므로 위 동작은 백엔드에서 검증·구현되지 않았다.

## Track ID가 필요한 경우

단일 이미지 YOLO API로 지속 Track ID를 만들 수 없다. 서버에서 이를 구현하려면 영상 프레임 스트림, 사람 탐지+다중객체추적(ByteTrack 등) 상태 저장, 세션 수명·동기화·개인정보/서버 부하 관리가 필요하다. 대안으로 프론트 MediaPipe에서 시작 시 선택한 포즈의 화면상 기준점과 랜드마크 연속성을 유지하는 방법이 있으며, 현재 구조·부하에는 이 방법이 더 작다.

플레이리스트 모드에서 복귀 시 YOLO 재점검이 확정되면, 복귀 이벤트에서 기존 환경 점검 API를 한 번 호출하는 정책을 추가한다. 운동 중 상시 YOLO 추론 또는 새 스트리밍 API는 별도 승인 후 설계한다.
